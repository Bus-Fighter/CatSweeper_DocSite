    WebSocket-Based Debugger Migration

    Overview

    Successfully replaced the EngineDebugger workflow with a WebSocket-based client/server architecture to avoid the known issue where EngineDebugger loses binding when the solution is rebuilt.

    Architecture

    Editor Side (GameToolsPlugin)

    • WebSocket Server: Starts when the plugin enters the tree on port 8080
    • Message Router: Routes incoming messages to appropriate GameToolWindow instances based on channel names
    • Protocol: JSON-based messages with format { "Message": "channel:message_name", "Data": [...] }

    Runtime Side (GameDebugger)

    • WebSocket Client: Singleton instance that connects to editor on port 8080
    • Async Connection: Connects asynchronously when the game starts
    • Message Sending: Converts Godot types to JSON and sends via WebSocket

    Files Modified

    1. CatSweeper.csproj

    • Added reference to Modules\WsConnect\WsConnect\WsConnect.csproj

    2. GameToolsPlugin.cs (addons/GameTools/)

    Changes:

    • Removed GameToolsDebuggerPlugin dependency
    • Added WsServer instance
    • Added GameToolsMessageRouter for routing messages
    • Implemented WebSocket server lifecycle (start/stop)
    • Added message handlers: OnClientConnected, OnClientDisconnected, OnMessageReceived

    3. GameToolsMessageRouter.cs (NEW - addons/GameTools/)

    Purpose:

    • Routes WebSocket messages to appropriate GameToolWindow instances
    • Converts JSON data back to Godot types (Array, Dictionary, Vector2I, etc.)
    • Handles complex type conversions from JsonElement to Variant

    Key Methods:

    • RegisterWindow(): Registers a GameToolWindow for a specific channel
    • RouteMessage(): Parses message format "channel:message_name" and routes to window
    • ConvertToGodotArray(): Converts JSON arrays to Godot Arrays
    • ConvertJsonElementToGodotValue(): Handles all JSON type conversions

    4. GameDebugger.cs (NEW - Script/Core/)

    Purpose:

    • Singleton runtime debugger that replaces EngineDebugger
    • Connects to editor WebSocket server at ws://localhost:8080
    • Sends debug messages from game to editor

    Key Methods:

    • Instance: Singleton accessor
    • IsActive(): Returns true if connected to editor
    • ConnectAsync(): Establishes WebSocket connection
    • SendMessage(): Sends messages in format "channel:message_name" with Godot Array data
    • ConvertArrayToJson(): Converts Godot types to JSON-serializable objects
    • ConvertVariantToJson(): Handles Variant type conversions (Vector2I, Dictionary, Array, etc.)

    5. StageController.cs (Script/Stage/)

    Changes:

    • Added using CatSweeper.Core; for GameDebugger
    • In _Ready(): Calls GameDebugger.Instance.ConnectAsync() under #if TOOLS
    • Replaced EngineDebugger.SendMessage() with GameDebugger.Instance.SendMessage() in two locations:
      • stage:stage_initialized message
      • stage:grid_updated message

    Message Flow

    From Game to Editor:

    1. Game calls GameDebugger.Instance.SendMessage("stage:grid_updated", data)
    2. GameDebugger converts Godot types to JSON
    3. Message sent via WsClient to WebSocket server
    4. GameToolsPlugin receives message
    5. GameToolsMessageRouter parses channel name
    6. Message routed to appropriate GameToolWindow (e.g., StageSessionWindow)
    7. Window's OnMessageCaptured() method processes the data

    Message Format:

    {
  "Message": "channel:message_name",
  "Data": [/* array of converted Godot types */]
}

    Type Conversions

    Godot → JSON (GameDebugger):

    • Vector2I/Vector2 → { x: number, y: number }
    • Dictionary → { [key: string]: any }
    • Array → any[]
    • Primitives → string/number/boolean

    JSON → Godot (GameToolsMessageRouter):

    • { x: number, y: number } → Vector2I
    • JSON Object → Godot.Collections.Dictionary
    • JSON Array → Godot.Collections.Array
    • Primitives → int/long/double/string/bool

    Benefits

    1. No Rebuild Issues: WebSocket connection persists across solution rebuilds
    2. Decoupled: Editor and runtime communicate via standard WebSocket protocol
    3. Flexible: Can add new channels/windows without modifying core infrastructure
    4. Debuggable: Can inspect WebSocket traffic with standard tools
    5. Extensible: Easy to add new message types and handlers

    Usage

    In Runtime Code:

    #if TOOLS
GameDebugger.Instance.SendMessage("channel:message_name", new Array()
{
    data1,
    data2,
    new Dictionary { { "key", value } }
});
#endif

    In Editor Plugin:

    public class MyToolWindow : GameToolWindow
{
    public override string channelName => "mychannel";
    public override string tabName => "My Tool";
    
    public override bool OnMessageCaptured(string message, Array data, int sessionId)
    {
        if (message == "message_name")
        {
            // Handle the message
            return true;
        }
        return false;
    }
}

    Testing

    Build succeeded with 0 errors and 140 warnings (all pre-existing).

    Notes

    • WebSocket server runs on localhost:8080
    • Connection is only active in editor (#if TOOLS)
    • WsServer and WsClient use infinite keep-alive mode for persistent connections
    • All type conversions use Variant.From() to ensure proper Godot type handling
