    Assembly Unload Diagnostics Guide

    Based on Microsoft Documentation: How to use and debug assembly unloadability in .NET

    Problem

    Godot C# hot-reload fails with:

    ERROR: modules/mono/mono_gd/gd_mono.cpp:791 - .NET: Failed to unload assemblies.

    This happens when references prevent the CLR from unloading the assembly.

    Installation

    The plugin is located at addons/AssemblyUnloadDiagnostics/.

    1. Open Project → Project Settings → Plugins
    2. Find "Assembly Unload Diagnostics" and enable it
    3. Two buttons will appear in the editor toolbar:
      • 🔍 Quick - Fast check for common blockers
      • 🔬 Full - Complete diagnostic scan

    Diagnostic Tools

    1. Diagnostics (Static Class)

    Static utility class that analyzes your code for common unload blockers.

    Quick Check (Automatic)

    Runs automatically when the plugin unloads (e.g., before rebuild):

    using AssemblyUnloadDiagnostics;

// Manual quick check
Diagnostics.QuickCheck();

    Manual Full Diagnostics

    using AssemblyUnloadDiagnostics;

// Run complete diagnostics
Diagnostics.RunFullDiagnostics();

// Or individual checks:
Diagnostics.ListLoadedAssemblies();
Diagnostics.TestUnloadability();
Diagnostics.QuickCheck();

    Configure Assembly Patterns

    // Add your own assembly patterns to check
Diagnostics.AssemblyPatterns.Add("MyCustomAssembly");

    2. ReferenceTracker

    Track specific objects to verify they get garbage collected.

    using AssemblyUnloadDiagnostics;

// Track objects you suspect might cause issues
public class MyClass : IDisposable
{
    public MyClass()
    {
        ReferenceTracker.Track("MyClass.instance", this);
        
        // Or use extension method:
        _myObject = new SomeObject().TrackForUnload("MyObject");
    }
    
    public void Dispose()
    {
        ReferenceTracker.Untrack("MyClass.instance");
    }
}

// Check which objects are still alive after GC
ReferenceTracker.CheckAliveReferences();

    3. Toolbar Buttons

    • 🔍 Quick - Runs QuickCheck() and ReferenceTracker.CheckAliveReferences()
    • 🔬 Full - Runs all diagnostics including assembly listing and unloadability test

    Common Blockers

    1. Static Fields with Object References

    // ❌ BAD - holds reference preventing unload
private static MyService _instance;

// ✅ GOOD - clear on cleanup
public static void Clear() => _instance = null;

    2. Event Subscriptions Not Unsubscribed

    // ❌ BAD
SomeEvent += MyHandler;

// ✅ GOOD
public void Dispose()
{
    SomeEvent -= MyHandler;
}

    3. Lambda Captures

    // ❌ BAD - captures 'this' implicitly
someCollection.Where(x => x.Value == this.MyValue);

// ✅ GOOD - static lambda, no capture
someCollection.Where(static x => x.Value > 0);

    4. Async Operations Not Completed

    // ❌ BAD - async task may still hold references
async void StartSomething()
{
    await SomeAsyncWork(); // If not completed, holds references
}

// ✅ GOOD - ensure async work completes or is cancelled
await _cancellationTokenSource.CancelAsync();

    5. Timers and Threads

    // ❌ BAD - timer holds callback reference
_timer = new Timer(_ => DoWork(), null, 0, 1000);

// ✅ GOOD - dispose timer
public void Dispose()
{
    _timer?.Dispose();
}

    Debugging Workflow

    1. Enable diagnostics:

      AssemblyCleanup.DiagnosticsEnabled = true;

    2. Track suspicious objects:

      ReferenceTracker.Track("StageSession", stageSession);

    3. Build and watch console output:

      • Look for ⚠ ALIVE: messages - these are potential blockers
      • Look for [STATIC] and [DELEGATE] warnings

    4. Fix identified issues:

      • Clear static references
      • Unsubscribe from events
      • Dispose resources
      • Use static lambdas where possible

    5. Verify fix:

      • Rebuild and check if unload succeeds
      • Check ✓ COLLECTED: messages

    Workarounds

    If you can't find the blocker, you can:

    1. Disable hot-reload in .csproj:

      <PropertyGroup>
    <GodotDisableHotReload>true</GodotDisableHotReload>
</PropertyGroup>

    2. Disable in Editor Settings: Editor → Editor Settings → Dotnet → Editor → Reload Assemblies On Build → false

    3. Restart editor after each rebuild (safest option)
